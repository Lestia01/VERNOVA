# VERNOVA — Troubleshooting & Diagnostic Guide

Panduan diagnostik sistematis untuk mendeteksi, mengisolasi, dan menyelesaikan kendala teknis pada platform **VERNOVA Smart Sorting Factory**.

---

## Tabel Diagnostik Komprehensif (14 Kasus Umum)

| No | Gejala Permasalahan | Kemungkinan Penyebab | Langkah Pengecekan | Solusi / Tindakan Perbaikan | Indikator Verifikasi Sukses |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | **ESP32 Wi-Fi tidak terhubung / IP tidak ditemukan** | SSID/Password salah pada firmware; router membatasi client baru; jangkauan sinyal lemah. | Buka Serial Monitor Arduino IDE (115200 baud). Amati output saat ESP32 booting. Periksa daftar client di router. | Perbarui `WIFI_SSID` dan `WIFI_PASS` di `esp32_vernova_sorting.ino`. Pastikan ESP32 terhubung ke frekuensi 2.4 GHz (ESP32 tidak mendukung 5 GHz). | Serial monitor mencetak: `WiFi connected, IP: 192.168.x.x`. Ping IP berhasil dari komputer. |
| **2** | **ESP32 HTTP request ditolak CORS (Cross-Origin)** | Header HTTP CORS (`Access-Control-Allow-Origin`) belum diaktifkan di WebServer ESP32. | Buka Developer Tools browser (F12) -> Console. Cari error bertuliskan `blocked by CORS policy`. | Pastikan baris `server.sendHeader("Access-Control-Allow-Origin", "*");` ada pada handler `/api/status`, `/api/mechanism`, dan `/api/sort`. | Request `curl -I http://<ip>/api/status` mengembalikan header `Access-Control-Allow-Origin: *`. |
| **3** | **Web Bluetooth tidak mendeteksi ESP32 atau micro:bit** | Bluetooth browser dinonaktifkan; situs tidak berjalan di HTTPS atau localhost; perangkat sedang terhubung ke perangkat lain. | Pastikan URL browser adalah `https://` atau `http://localhost`. Cek apakah Bluetooth PC aktif. | Putuskan koneksi Bluetooth di perangkat lain (ponsel/laptop lain). Buka `chrome://bluetooth-internals` untuk memeriksa adapter host. | Dialog pemindaian Web Bluetooth Chrome memunculkan nama `VERNOVA_ESP32_BLE` atau `BBC micro:bit`. |
| **4** | **micro:bit tidak merespon perintah UART** | Firmware MakeCode belum menyertakan ekstensi Bluetooth; pairing mode belum selesai; format delimiter perintah salah. | Cek apakah tampilan LED micro:bit menampilkan ikon centang setelah pairing. Periksa kode MakeCode UART handler. | Flash ulang hex firmware dengan ekstensi `bluetooth`. Pastikan menggunakan delimiter yang sesuai (`#` atau `\n`). | micro:bit membalas string `ACK:ARM:READY` atau `ACK:SERVO:READY` di log transaksi. |
| **5** | **Servo tidak bergerak atau bergetar tanpa gerakan** | Catu daya servo tidak mencukupi (under-voltage); pin PWM salah; ground ESP32 dan power supply servo tidak terhubung (common ground). | Ukur tegangan VCC servo dengan multimeter saat diam dan saat bergerak. Cek apakah tegangan drop di bawah 4.5V. | Gunakan adaptor eksternal 5V 2A-3A khusus untuk servo. Sambungkan kabel GND adaptor ke pin GND ESP32/micro:bit. | Servo bergerak mulus tanpa jitter atau restart mikrokontroler saat manuver. |
| **6** | **Robotic arm macet di tengah gerakan** | Beban mekanis terlalu berat; kabel motor tertarik; servo limit tercapai (sudut di luar batas aman); brownout reset. | Amati Serial Monitor apakah ESP32 melakukan reboot sendiri saat arm bergerak. Periksa pergerakan engsel secara manual saat mati. | Longgarkan baut engsel arm jika terlalu rapat. Batasi rentang sudut servo di firmware (misal 15° hingga 165°). Tambahkan kapasitor 1000uF pada jalur power servo. | Arm menyelesaikan gerakan pick-and-place tanpa kendala dan kembali ke posisi standby. |
| **7** | **AI salah mendeteksi mekanisme (Arm vs Servo)** | Model AI dilatih hanya dengan 3 kelas warna (`merah`, `kuning`, `biru`) tanpa varian mekanisme; label anotasi terbalik. | Buka modal **Mapping Kelas AI** di dashboard. Periksa apakah model aktif adalah model 6-kelas atau 3-kelas legacy. | Jika menggunakan model 3-kelas, atur pemetaan manual di modal (misal: Merah -> Servo, Kuning -> Arm). Jika melatih ulang, gunakan dataset 6-kelas (`merah_arm`, `merah_servo`). | Card telemetri transaksi menampilkan mekanisme yang sesuai dengan label target. |
| **8** | **Model legacy 3-kelas tidak memicu gerakan motor** | Konfigurasi pemetaan mekanisme (`legacyMechanismMap`) belum disetel, sehingga sistem menolak instruksi (*Safety Fallback*). | Cek console browser untuk error code `MECHANISM_UNDEFINED`. | Buka tombol **Mapping Kelas AI**, pilih mekanisme default untuk setiap warna, lalu klik **Simpan Pemetaan**. | Transaksi lolos ke tahap `COMMAND_QUEUED` dan Stage 1 dieksekusi tanpa error penolakan. |
| **9** | **Mode Manual tidak mengirim perintah ke perangkat** | Pilihan Target Device atau Connection Type belum aktif/terhubung; parameter warna belum dipilih. | Periksa pill indikator koneksi di panel manual. Cek apakah tombol **KIRIM PERINTAH** memunculkan pesan validasi. | Klik tombol koneksi perangkat di bar konfigurasi atas terlebih dahulu. Pilih Warna dan Mekanisme sebelum menekan tombol Kirim. | Panel telemetri memperlihatkan transaksi manual dimulai (`sortingMode: "MANUAL"`). |
| **10** | **Mode Auto mengirim perintah ganda untuk satu objek** | Debounce interval terlalu singkat; objek berhenti terlalu lama di depan kamera; NMS belum aktif di backend. | Periksa log transaksi: apakah ada 2 transaksi dalam rentang waktu < 2 detik untuk objek yang sama. | Naikkan *Detection Debounce* di menu pengaturan menjadi minimal 2500 ms. Pastikan backend YOLO menjalankan Non-Maximum Suppression (NMS). | Objek hanya memicu satu kali siklus transaksi Stage 1 & Stage 2 selama melintasi area kamera. |
| **11** | **Kamera tidak dapat diakses (Black Screen / Error)** | Izin kamera ditolak di browser; kamera sedang digunakan oleh aplikasi lain (OBS/Zoom/Teams); format video tidak kompatibel. | Periksa ikon kamera di address bar browser. Cek task manager untuk aplikasi yang mengunci webcam. | Berikan izin `Allow` untuk Camera di pengaturan browser. Matikan aplikasi lain yang mengakses kamera, lalu muat ulang halaman. | Video stream kamera tampil jernih di canvas AI Vision dengan FPS counter aktif. |
| **12** | **Status transaksi selalu berakhir TIMEOUT** | Mikrokontroler sibuk atau freeze; koneksi jaringan putus saat Stage 1/2; firmware tidak mengirimkan string ACK balasan. | Periksa apakah LED TX/RX pada board mikrokontroler berkedip saat perintah dikirim. Cek Serial Monitor. | Tambahkan log `Serial.println("ACK:...")` pada firmware setelah menerima JSON/perintah. Periksa apakah delay motor memblokir loop utama (*gunakan millis() bukan delay()*). | Status transaksi berpindah dari `AWAITING_MECHANISM_ACK` ke `SORTING` sebelum 3000 ms. |
| **13** | **Sensor verifikasi tidak pernah bernilai true (`verified`)** | Sensor IR / Proximity terputus; pin input salah di firmware; logika sensor terbalik (Active LOW vs Active HIGH). | Uji sensor dengan meletakkan tangan di depan sensor IR: amati apakah LED indikator modul sensor menyala. | Periksa koneksi kabel sinyal sensor ke pin GPIO ESP32. Sesuaikan pembacaan digital di firmware (`digitalRead(SENSOR_PIN) == LOW`). | Card riwayat mencatat badge hijau `VERIFIED` dan field `sensorVerified: true`. |
| **14** | **Firebase RTDB gagal mencatat transaksi** | Konfigurasi Firebase API Key tidak valid; Firebase Security Rules memblokir penulisan anonim (`permission_denied`); koneksi internet terputus. | Buka browser Console: periksa adanya pesan error Firebase bertuliskan `PERMISSION_DENIED` atau network error. | Buka Firebase Console -> Realtime Database -> Rules. Pastikan rules mengizinkan tulis: `".read": true, ".write": true` (atau dengan token valid). | Riwayat sortasi langsung bertambah di tabel history dashboard dan tersimpan di cloud. |

## Prosedur Pelaporan Kendala

Jika masalah berlanjut setelah mengikuti langkah di atas:
1. Unduh log transaksi lokal melalui tombol **Ekspor Log** di dashboard.
2. Salin log Serial Monitor Arduino IDE selama proses booting dan transaksi berlangsung.
3. Laporkan isu melalui GitHub Issues repository `Lestia01/VERNOVA` dengan menyertakan versi firmware dan log di atas.
